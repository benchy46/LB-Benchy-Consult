So don't hand-edit Toolbox/template files locally — those changes get overwritten on the next sync. If you need a new fastener size or template change for the whole team, ping me and we'll update the master so everyone gets it." — i.e. a stated escalation path so the one-way constraint doesn't just become a silent trap.

## Recurring Themes / Principles Observed

- **Owns the team's shared infrastructure end-to-end** — CAD toolbox/templates, slicer presets, print farm, laser cutter, mech room, workstation tidiness, Notion/Slack wiring. This is unglamorous stewardship work he does personally and visibly, not something he has delegated.
- **Will reverse his own recent decision without ceremony when it underperforms** — the Toolbox network-read → local-sync change is a self-correction inside a month, framed as a fix for a symptom the team was feeling ("if SolidWorks has been lagging or freezing"), with no defensiveness about the earlier rollout.
- **Always names the new constraint a fix introduces** — the one-way sync trap, plus the escalation path around it. Same instinct as flagging the limiting case when widening a tolerance (`omega-station-internal`, 2024-11-20).
- **Broadcast format is consistent:** `<!channel>` → why it matters → numbered steps → what runs automatically afterwards → the one gotcha → "shout if it breaks." Low-ceremony, operationally complete.
- **Justifies rules by shared consequence** — tangled filament jams *everyone's* printers; slow Toolbox reads freeze *everyone's* SolidWorks. Rarely "because I said so."
- **Reduces friction before increasing pressure** — build the rack, name the second password-holder, ship the auto-sync — then ask for compliance.
